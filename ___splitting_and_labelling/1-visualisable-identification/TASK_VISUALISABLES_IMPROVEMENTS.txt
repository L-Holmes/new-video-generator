THE RULES. READ THESE FIRST. THEY OVERRULE EVERY TASK BELOW.

1) NO WORD IS EVER WRITTEN DOWN.
   Not one rule below may name a word. A rule that names a word fixes one
   script and no other. Name a TYPE instead, and it works on every word in
   English including the ones no script has used yet:
       WordNet supersenses      noun.artifact, noun.attribute, verb.motion
       WordNet taxonomy nodes   property.n.02, quality.n.01
       WordNet adjective classes  adj.pert (relational), adj.ppl
       spaCy tags / deps / NER  VBN, JJR, neg, nummod, acomp, GPE, NORP
       Brysbaert thresholds     a number on 1..5, applied to every word alike
   THE ONE EXISTING EXCEPTION, AND ITS LIMIT: shared_text_logic.py already
   holds word lists (WEAK_VERB_LEMMAS, GENERIC_TOPIC_NOUNS, APPROXIMATOR_WORDS)
   and they stay, because the sentence splitter shares them. NO NEW WORD MAY BE
   ADDED TO ANY OF THEM BY THIS WORK. Closed grammatical classes -- determiners,
   negators, cardinals, modals -- are the only thing that counts as reading a
   tag rather than writing a lexicon.

2) NO AI DECIDES WHAT IS VISUAL.  (TODO.md, in shouting.)
   ALLOWED  a local model with a pinned checkpoint, run offline, whose answer
            is a score or a vote that THIS code then judges by its own written
            rules -- the coreference ensemble already is one.
   BANNED   a network call; a chat model; anything handed a prompt whose PROSE
            is taken as the answer.

3) LICENCE: MIT / Apache-2.0 / BSD only. This ships in paid software. Check
   before installing anything -- see task 2, where the obvious choice is AGPL.

4) THE TEMPLATE TEXT NEVER CHANGES. The words on screen are the words the
   viewer hears. Only the SEARCH TERM may be rewritten, and no character offset
   may move -- the abstract-terms map is keyed by offsets into
   join_segments(), and moving one desyncs the whole file.

5) NOTHING RAISES. A missing model, corpus or data file degrades the term and
   never stops the run. facts_for_lines() is wrapped per row for this reason,
   and every lookup in _knowledge_base.py answers "no opinion" rather than
   throwing. Keep that property.

6) NOTHING DISAPPEARS SILENTLY. Candidate.dropped_by / entry.dropped record
   every drop. Every new drop or rewrite records why, so the working shows.

7) NO THIRD PARSE. Two parses (sm for the extractor, trf for the resolver) is
   the current, measured, justified state. Three is not.

2) THEME EXTRACTION -- what the script is ABOUT, typed
--------------------------------------------------------------------------------
WHAT   Work out, per script, what it is about, and give each theme a KIND.
       Compute internally over three scopes so a theme that has ENDED is not
       applied later: whole script, text-so-far (segments[:i+1]), and a window
       of N segments around i.

DATA SHAPE -- keep it flat, no Theme class
       An enum for the kinds, and TWO PLAIN FIELDS on the slot map:

           class ThemeKind(str, Enum):     # str, so it serialises as "place"
               PLACE   = "place"           # and the map stays plain JSON
               ERA     = "era"
               CULTURE = "culture"
               SUBJECT = "subject"

           ... "theme_kind": "place", "theme_text": "Egypt", ...

       ONE theme per slot, chosen by the engine. The scopes are working, not
       output. Do not add a Theme object, a list of themes, or a nested dict --
       the map is read by three other files and its simplicity is the point.

WHAT WITH -- researched 2026-09-04
   KeyBERT      MIT. v0.9.0, Feb 2025, actively maintained. The accuracy winner
                in the published keyword-extraction benchmarks, and it works on
                ONE document, which is what a script is.
   Model2Vec    MIT, maintained, numpy-only inference. Use it as KeyBERT's
                backend so we add NO torch and NO sentence-transformers:
                    uv pip install keybert --no-deps scikit-learn model2vec
                    from model2vec import StaticModel
                    kw = KeyBERT(StaticModel.from_pretrained(
                                     "minishlab/potion-base-8M"))
                ~8M params, CPU, offline once cached.
   spaCy NER    Already installed, and it supplies the KIND, so no word list:
                    GPE / LOC / FAC -> PLACE      DATE / TIME -> ERA
                    NORP            -> CULTURE    anything else -> SUBJECT
                NORP is how "Roman" is found: the script's own adjective, read
                off a tag. NEVER derive an adjective from a place name. If the
                script only ever says "Rome", CULTURE stays empty -- that is
                correct and much better than guessing.

   REJECTED, so nobody re-shops:
     YAKE      AGPL-3.0, commercial licence sold separately. Fails rule 3
               outright. TODO.md shortlists it; it cannot be used.
     BERTopic  clusters a CORPUS into topics. We have one script. Wrong shape.
     textacy   Apache-2.0 but last release Apr 2023, one maintainer. Stale.
     Stanza    Apache-2.0 and healthy, but a second full NLP stack beside
               spaCy for no measured gain.
