AI_READ_THIS.txt
================
Standing conventions for this repo. Read before adding a feature that touches
the render pipeline. These are decisions already made — follow them rather than
re-deriving them.


1. FIXED-LENGTH ANIMATIONS IN VARIABLE-LENGTH SCENES
----------------------------------------------------
A scene's runtime comes from the narration audio, so it is not known when an
animation is authored and it is never the animation's natural length. Do NOT
speed the animation up, slow it down, or loop it to fit.

ALWAYS use the transition + hold pattern:

  Render TWO artefacts:
    - the TRANSITION: the animation itself, at its natural length, as an mp4.
    - the FINAL STILL: the animation's LAST FRAME, as a png. (Extract it from
      the mp4 with `ffmpeg -sseof`, so the still is by construction exactly
      what the animation settles on — never a re-render that might drift.)

  End the animation with a short SETTLE beat, and report where it starts as
  `min_playable_secs`. Everything before it is essential (the movement, the
  reveal); the settle exists to be trimmed.

  Then, once the scene's runtime is known (SCENE_GENERATORS, which has the
  audio timings), pick per scene:
    - runtime <  min_playable  ->  ONE entry: the FINAL STILL, baked to a
      static mp4 of the full runtime. The animation is NOT played. A clipped
      animation reads as a glitch; the finished picture reads as a choice.
    - runtime <= transition    ->  ONE entry: the transition, trimmed to the
      runtime. What is lost is settle, never the movement or the reveal.
    - runtime >  transition    ->  TWO entries, played back to back: the
      transition at its own length, then the final still held for the rest.

  The entries are `{path: trim_seconds}` dicts and the trims must sum to the
  scene's runtime exactly. Every trim must be <= its file's real duration.

  KEEP THE ANIMATION SHORT. Narration lines are brief — in a real script the
  median is about 1.3s and most are under 3s. A three-second animation is one
  that essentially never plays: every scene falls to the still and you are left
  wondering why your transition "didn't show". Budget against the SCRIPT, not
  against what looks good in isolation.

  Cache the render under a key covering EVERY input — the data, but also the
  durations and colours. `timeline_2026_to_1600` looks like a cache key and is
  not one: shorten the travel time and it serves the old video forever.
  ___visuals/maths/timeline.py::_cache_key hashes the lot.

  Live examples:
    ___visuals/SCENE_GENERATORS.py  generate_maths_scenes   (timeline)
    ___visuals/SCENE_GENERATORS.py  generate_joint_scenes   (intro then loop)


2. STRUCTURED INPUT: THE `data` COLUMN
--------------------------------------
Most media types are driven by `search_term`. Types that need something a
search term cannot express (a timeline's year; a chart's slices) read
`row["data"]`, one object per scene.

Do NOT add a new top-level column per type. Instead:
  - declare the inputs in CONFIG.MEDIA_TYPE_DATA_FIELDS as DataField rows.
  - CONFIG.normalise_scene_row validates + coerces `data` against them on load,
    so a generator can trust the values' types.
  - MANUAL_TAGGING builds its data form FROM that table. No per-type UI code.


3. NO LATEX
-----------
manim is installed and used for maths animations, but LaTeX is not, and should
not be. Manim's DecimalNumber/MathTex shell out to `latex` by default. Pass
`mob_class=Text` (or `label_constructor=Text` on a NumberLine) so every number
renders through Pango instead. See ___visuals/maths/timeline.py.

manim needs system cairo + pango:
    sudo apt install -y libcairo2-dev libpango1.0-dev pkg-config python3-dev


4. ADDING A MATHS MEDIA TYPE
-----------------------------
  1. CONFIG.MEDIA_TYPE_CATALOG: an entry tagged Tag.MATHS.
  2. CONFIG.MEDIA_PROPERTIES:   a property row (usually all-default).
  3. CONFIG.MEDIA_TYPE_DATA_FIELDS: what goes in its `data`.
  4. CONFIG.TERM_OPTIONAL_TYPES: add it (its input is `data`, not a term).
  5. ___visuals/maths/<type>.py: a render function returning
     (transition_mp4, final_png, transition_seconds) — see point 1.
  6. SCENE_GENERATORS._MATHS_RENDERERS: one line.
The manual tagger picks it up on its own: its maths tab is built from the
catalog, and its data form from MEDIA_TYPE_DATA_FIELDS.


5. CACHE LAYERS — WHAT A RESET SHOULD AND SHOULD NOT DELETE
------------------------------------------------------------
Inside <NAME>-CACHE/, these files each gate an EXPENSIVE stage. Deleting one
does not "clean up"; it re-runs minutes of work.

  footage_candidates.json        Pexels + Wikipedia metadata (Phase A).
                                 Deleting it re-scrapes every scene.
  stock_footage/history.json     The url -> local-path INDEX (Phase B).
  AUDIO/<stem>.sentences.json    Whisper: the silence cutdown.
  AUDIO/<stem>.processed.wav     ...same stage; both must survive.
  script_timings_seconds.json    Whisper: the script/audio synchroniser.
  stickman_scenes/               Paid fal.ai image generation. Same for
  stickman_joint_scenes/         stickman_joint_scenes/ and ai_edit_scenes/.
  ai_edit_scenes/
  maths_scenes/                  manim renders (tens of seconds each).

  So `find <NAME>-CACHE -name "*.json" -delete` is the WORST possible reset:
  it hits four of the above and re-runs whisper, the metadata scrape and the
  downloads, while leaving the media files it just orphaned.

Everything else regenerates cheaply from ffmpeg (blank_scenes/, map_scenes/,
joint_scenes/, collage_scenes/, decorate_scenes/, previous_previews/) and is
safe to delete. final_script_to_clips.json is a snapshot of the review picks
for the ai_edit preview, rewritten before it is read — deleting it costs
nothing.

To force a fresh render but keep the slow work:
    rm -rf <NAME>-OUTPUT/output.mp4 <NAME>-CACHE/output_video_final.mp4 \
           <NAME>-CACHE/{joint,blank,map,collage,decorate}_scenes

Every cache check must be able to REBUILD ITS OWN INDEX from what is on disk.
The downloaders are the model: a media file's name is a hash of its URL, so
_already_downloaded() trusts the file at that path even when history.json is
gone, and re-indexes it. Follow that pattern for any new cache — an index is a
speedup, never the only record that the work was done. Write files atomically
(.part + os.replace) so a killed run never leaves something a later run will
mistake for finished output.


6. GROUPS (rule of n)
---------------------
A group is written the way it reads on screen: the first line carries a real
base (`stock` / `ai_stock`) + the `group` modifier, and every line that joins
it carries `hold_previous` + `group`. `hold_previous` is only the SPELLING —
CONFIG.resolve_group_continuations() rewrites those rows to the group's real
base immediately after load, because every stage downstream dispatches on
media_type and each cell fetches its OWN picture from the group's base.

If you read the search-term json RAW (rather than taking main.py's in-memory
rows), you MUST call resolve_group_continuations() on it first, or you will
silently skip every cell but the first.
